# Глубокая диагностика — 18.11.2026

«Настройки → Предполётная проверка → **Глубокая диагностика**» (и кнопка «Диагностика» в ошибке без автоматического исправления). MONO не только читает настройки, но и активно проверяет каждую систему, а потом пишет выводы простыми словами: что не так и что сделать. Отчёт можно скопировать или сохранить в файл.

## Что проверяется

| Система | Как проверяется | Какой вывод можно получить |
|---|---|---|
| Ядро | Время ответа; **журнал ядра** — все предупреждения и ошибки сервера плюс каждый запуск. Журнал хранится на диске и **переживает перезапуск**, поэтому падение тоже видно | «Ядро перезапускалось 4 раза за час» и причина в журнале |
| Архив | Где лежит (Документы, OneDrive, сетевая папка — без пути); пробная запись файла с замером времени; свободное место в часах записи; число записей по состояниям | Запись блокирует «Контролируемый доступ к папкам»; медленный диск или сетевая папка; повреждённые и прерванные записи |
| Звук Windows | Все входы: состояние, звук по умолчанию, выключен ли, громкость; запрет доступа к микрофону; кто сейчас держит микрофон; готовность системного модуля записи | Микрофон выключен, громкость 0, отключён, занят Zoom |
| **Живой микрофон** | Окно открывает микрофон на 1,5 с (только если доступ уже выдан — без внезапного запроса) и меряет пик, RMS, перегрузку, время открытия, частоту и состояние дорожки | «Открылся, но передаёт полную тишину» — признак аппаратного выключателя или не того входа; `NotReadableError` — занят или проблема драйвера; перегрузка |
| Groq | Служебный запрос со временем ответа; остаток лимитов из заголовков `x-ratelimit-*`; есть ли модель распознавания; **настоящая сетевая причина** сбоя (`ENOTFOUND`, `ECONNREFUSED`, ошибка сертификата, тайм-аут) | DNS или нет интернета; HTTPS подменяет антивирус или прокси; ключ не принят; лимит исчерпан |
| Окно | Видеокарта (рендерер WebGL), частота и ровность кадров, зависания интерфейса больше 50 мс с момента запуска, память окна, батарея, сеть, офлайн-кэш | «Графика работает без видеокарты — обновите драйвер»; окну не хватает памяти |
| Расшифровка | Задания по состояниям и последние ошибки | Повторяющаяся ошибка Groq |
| Система | ОС, процессор, ядра, память и свободная память, версия FFmpeg | Почти закончилась оперативная память |

## Приватность
В отчёт **не попадают** названия записей, текст, ключи и пути к файлам. Тексты ошибок проходят очистку: из них вырезаются `gsk_…`, `Bearer …`, пути Windows и Unix, адреса почты. Названия звуковых устройств остаются: по ним видно, какой микрофон проверялся. Сквозной тест проверяет, что в скопированном отчёте нет пути к папке данных и ключа.

## Проверено
`tests/diagnostics.test.mjs`: очистка, журнал между перезапусками, выводы, проба Groq, устойчивость к отказу частей.
`tests/e2e/diagnostics.e2e.mjs`: настоящий Chromium, живой (фальшивый) микрофон измерен, Groq на закрытом порту → «Нет связи с Groq, ECONNREFUSED», два запуска в журнале, в отчёте нет путей и ключа.

## НЕТ ДАННЫХ ДЛЯ НАДЁЖНОГО ВЫВОДА
- Пороги (тишина ≤ −90 dBFS, перегрузка > 1 % отсчётов, медленные кадры > 20 %) выбраны инженерно, а не подобраны по статистике реальных ноутбуков.
- Определение «кто держит микрофон» по журналу Windows — эвристика (см. AUDIT-2026-11-18, раунд 2).

## Защитная программа отказывает MONO в звуке (20.11.2026)

Отчёт пользователя: Windows ответила `E_INVALIDARG` (0x80070057) на все шесть способов открыть поток, окно получило `NotReadableError`. Так было на двух разных микрофонах (Intel Smart Sound и USB). При этом Discord и Манго Контакт-Центр в то же время записывали тот же микрофон. В dxdiag в стеке камеры виден фильтр `KLIF.KES-14-0`, то есть Kaspersky Endpoint Security 14.

Почему это Kaspersky, а не драйвер:
- Kaspersky Endpoint Security 12.5 по умолчанию отдаёт аудио- и видеопоток только группе «Доверенные». Группам «Слабые ограничения», «Сильные ограничения» и «Недоверенные» он запрещён [1]. В 11.9 «Слабым ограничениям» поток ещё разрешался [1a].
- Модуль «Предотвращение вторжений» проверяет всю цепочку родительских процессов, и действует самое строгое право. Это сделано, чтобы недоверенная программа не пользовалась доверенной [2]. Поэтому Chrome, запущенный из MONO, тоже теряет микрофон.
- Тот же отпечаток описан независимо: на компьютере с Kaspersky каждый `IAudioClient::Initialize` внутри процесса (все устройства, форматы и флаги) и `waveInOpen` падали с `E_INVALIDARG`. WebView2, запущенный дочерним процессом, получал `NotReadableError`. Обычный браузер пользователя писал нормально [3].
- Вендор ProCall: ошибка `IAudioClient::Initialize()` устраняется правом на доступ к устройствам записи звука в политике Kaspersky Security Center [4]. Похожий случай разобран на форуме Kaspersky: неизвестные KSN файлы попадали в «Слабые ограничения» и теряли доступ ко всем устройствам записи [5].
- Новые права начинают действовать только после перезапуска программы [6].

Что делает MONO:
- Узнаёт Kaspersky через Центр безопасности Windows (`root/SecurityCenter2 AntiVirusProduct`) или по процессам `avp`/`avpui`.
- Сопоставляет это с ответами модуля (все способы → `E_INVALIDARG`) и с тем, кто ещё пишет микрофон.
- Называет причину и путь в настройках Kaspersky. Для рабочего компьютера советует обратиться к администратору.
- Больше не говорит «микрофон может держать другое приложение» и «сбой драйвера».
- Кнопка «Открыть в браузере» копирует адрес MONO. Браузер пользователь открывает сам: процесс, запущенный самим MONO, унаследовал бы его ограничения [2]. Обходить защитную программу MONO не пытается.

Проверено: юнит-тесты `tests/diagnostics.test.mjs` и сквозной тест в Chromium (`features.e2e.mjs`, ответ сервера с данными Windows подставлен).

НЕТ ДАННЫХ ДЛЯ НАДЁЖНОГО ВЫВОДА:
- Точные названия пунктов меню в KES 14 по-русски. Страницы support.kaspersky.com из этой среды недоступны; названия взяты из документации KES 12 и вторичного источника [7].
- Помогает ли перенос в «Доверенные» без отключения наследования для дочерних процессов. Документация разных версий расходится [2].
- Получит ли микрофон браузер, если до этого он не был запущен. Кто окажется родителем процесса, зависит от того, как его открыть.
