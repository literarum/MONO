# MONO UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** R-001…R-012: очистить интерфейс и создать единые компоненты без регрессий существующих действий.
**Architecture:** Существующие маршруты и данные сохраняются; переиспользуемые модули управляют контролами, слоями, scroll и motion. CSS tokens — единственный источник семантических размеров.
**Tech Stack:** ES modules, HTML/CSS, node:test, реальный браузер/WebView.
**Spec:** ../../MONO-0.5-SPEC.md; общий контракт и точные значения: 2026-10-16-mono-master.md.

## Global Constraints

Наследует все Global Constraints master-плана, в частности 22 удаления, spacing/motion tokens, custom scroll arrows, обе темы/четыре ширины/200% zoom, reduced-motion. Системные диалоги ОС остаются нативными.

### UI-2: Select и базовые контролы

**Files:** Create public/ui/select.js, public/ui/controls.css, public/ui/layers.js, tests/ui-components.test.mjs; Modify public/index.html, public/app.js.
**Interfaces:** `mountSelect(select: HTMLSelectElement): {sync():void,destroy():void}` — select остается моделью значения/change и доступным fallback до mount; кастомный контрол — единственная доступная интерактивная поверхность после mount. `openLayer({element,anchor,modal,onClose}): {close(reason):void}` владеет outside/Escape/focus/viewport.

- [ ] Зафиксировать RED: выбор первого/последнего/disabled option, Arrow/Home/End, Enter/Escape/Tab, typeahead с кириллицей, IME composition, программное изменение с sync, два mount/destroy и длинный option у нижнего края. Test assertions: одно change на выбор; Escape не меняет value; нет утечки focus/listeners; popup целиком в viewport.
- [ ] Реализовать Select/layer, заменить все существующие select включая player-speed и динамический export-dialog; добавить стили native-semantic checkbox/radio/switch/range/number/password. Не вводить фиктивные checkbox в продукт только ради демонстрации.
- [ ] Run `node --test tests/ui-components.test.mjs`; state/geometry helpers покрываются детерминированно, DOM/keyboard сценарии — реальным браузером с сохраняемым acceptance log. Каждый компонент имеет checked/disabled/error/focus, radio keyboard и indeterminate где применимо.

### UI-3: единый ScrollArea

**Files:** Create public/ui/scroll-area.js, public/ui/scroll-area.css, tests/scroll-model.test.mjs; Modify public/index.html, public/styles.css, public/ui/select.js, public/ui/layers.js, public/app.js.
**Interfaces:** `mountScrollArea(viewport: HTMLElement,{axes:'y'|'both'}): {refresh():void,destroy():void}`; `scrollMetrics({content,viewport,position,track,minThumb:24}): {thumb,offset,max,atStart,atEnd}` — pure model. Нативный scroll offset остается источником истины; gutter резервирует место.

- [ ] Реализовать собственные rail/thumb/arrow buttons, pointer capture и отмену удержания на blur/pointercancel; Resize/Mutation observers, корректную очистку. Обернуть main/sidebar/dialog/select/transcript/редактируемые поля без второй штатной полосы; сохранить textarea selection/IME/caret scrolling.
- [ ] Run `node --test tests/scroll-model.test.mjs`; реальные wheel/touch/keyboard/drag/arrow проверки на вложенных областях. Focus scroll не выталкивает активный элемент под player; aria orientation/value соответствует offset.
- [ ] Сравнить геометрию content/gutter и скриншоты обеих тем на всех ширинах/200% zoom. Проверить длинную правку кириллицей и повторный render без роста числа handlers. Сохранить checkpoint.
