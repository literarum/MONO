# Портативная версия и обновление из файла

## Портативная версия
`MONO-portable-<версия>.zip` из CI (артефакт `MONO-portable-windows`). Распакуйте папку куда угодно, в том числе на флешку, и запускайте `MONO.exe`. Установка не нужна. Записи, настройки и журнал хранятся рядом, в `MONO-DATA`: на это указывает файл-метка `MONO.portable`. Без метки, как в установленной версии, данные хранятся в `%LOCALAPPDATA%\MONO Transcribe`.

`MONO.exe` — небольшой запускатель на C (`native/windows/launcher/MONO.c`). Он находит папку данных, ставит готовое обновление, если оно есть, и запускает MONO. MONO открывается отдельным окном вашего браузера.

## Обновление без сервера
Файл `.monoupdate` — подписанный пакет:
- в начале метка `MONOUPD1`;
- затем манифест (JSON): версия и для каждого файла путь, размер и SHA-256;
- затем подпись манифеста Ed25519 (64 байта);
- затем сами файлы.

Подпись покрывает манифест, а манифест — каждый байт пакета.

1. «Настройки → Обновление → Установить из файла…». MONO проверяет подпись открытым ключом, который входит в сборку (`backend/local/update-key.pem`). Затем он проверяет, что версия новее, а пути безопасны: без `..` и абсолютных путей. Файлы распаковываются в `MONO-DATA\updates\staging`, хеш каждого сверяется. Только после этого папка становится `updates\ready` с меткой `READY`.
2. Пользователь закрывает окно MONO и запускает его снова. `MONO.exe` переименовывает `app` в `app.previous`, а `updates\ready\app` — в `app`. Это две операции переименования на одном диске, без копирования. Если вторая не удалась, первая отменяется. Результат записывается в `updates\applied.json`.
3. Отказы:
   - чужой ключ, изменённый байт, обрезанный файл, не новая версия — файл не принимается, уже проверенное обновление остаётся;
   - открыт MONO и папка занята — обновление ждёт следующего запуска.

Проверено:
- `tests/update-package.test.mjs` — подпись, подмена байта, обрезка, старая версия, пути, HTTP;
- на настоящем Windows в CI (`scripts/ci/update-roundtrip.mjs`): подписанное обновление загружается через тот же API, что и «Настройки», подделка отклоняется, `MONO.exe` при следующем запуске переключается на новую версию и сохраняет прежнюю.

## Однократная настройка подписи (для автора MONO)
Ключ подписи — секрет. Его нельзя хранить в репозитории или пересылать в чате.
1. `node scripts/release/update-key.mjs` создаёт `backend/local/update-key.pem` (открытый ключ, его нужно закоммитить) и `~/.mono-release/update-signing-key.pem` (закрытый).
2. Содержимое закрытого ключа добавьте в секрет репозитория `MONO_UPDATE_SIGNING_KEY` и сохраните резервную копию отдельно от компьютера.
3. С этого момента CI собирает рядом с портативной версией `MONO-update-<версия>.monoupdate`, а сборки с этим открытым ключом его принимают.

Пока ключ не создан, MONO честно сообщает: «В этой сборке не настроена подпись обновлений». Файл без проверяемой подписи он не установит.

## НЕТ ДАННЫХ ДЛЯ НАДЁЖНОГО ВЫВОДА
- Поведение антивирусов, в том числе Kaspersky, при замене папки `app` неподписанным `MONO.exe`. В CI антивируса нет.
- Обновление самого `MONO.exe` и среды выполнения (Python, Node, FFmpeg). Пакет меняет только папку `app`. Чтобы обновить остальное, нужна новая портативная версия или установщик.
