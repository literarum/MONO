# [ИСТОРИЯ 0.2.0] MONO TRANSCRIBE 0.2.0 — повторный аудит и разработка

Дата: 16.10.2026. Объект: исходники предыдущей версии `MONO_TRANSCRIBE_SPA_PWA.zip` (файлы `public/`, `server.mjs`, `core.mjs`).
Исходная версия сохранена в предоставленном ранее архиве; текущая рабочая копия — следующий релиз.
Отдельного агента-критика нет: четвёртый аудит выполняется как **SELF-CRITIC**.

## Contract / критерии завершения итерации

1. Исходный проект реально изучен; исправлены >=20 доказуемых дефектов/режимов отказа, не косметический список.
2. Безопасность: секрет Groq не уходит в браузер, сервер не публикуется без авторизации, передача аудио требует подтверждения.
3. При потере ответа на создание задания обеспечено восстановление без повторной отправки; завершённые сегменты не оплачиваются заново из-за рестарта.
4. Серверные JSON-статусы и результаты сохраняются атомарно; при отмене прекращается внешний запрос и локальная обработка.
5. Данные из Groq не теряются из-за некорректных timestamps; экспорт ожидает сохранения правок.
6. Три независимых **прохода методики**: review/тесты → интеграция → визуальный UX/adversarial.
7. Артефакт воспроизводим и содержит полный source, тесты, README, манифест PWA.

## Проверка 1 — исходники + deterministic tests

Проверено:
- `npm run check` — Node syntax check `server.mjs`, `public/app.js`, `public/db.js`, `public/sw.js` = OK.
- `npm test` — 9/9 passed.
- `core.mjs`: 4-часовой план из 60 сегментов; invalid overlap, fallback provider timestamps, monotonic ordering.
- Единичные исправления сопоставлены с реальными кодовыми участками v0.1.0.

## Проверка 2 — HTTP + FFmpeg + аварийное восстановление

Запускались реальные Node subprocess, HTTP-заглушка Groq и FFmpeg/FFprobe; **без внешних платных запросов**:
- WAV → upload → FLAC → HTTP 429 → `Retry-After` → повтор → segment JSON → transcript.
- Проверены `model`, `language=ru`, `verbose_json` и Authorization только в outbound request.
- Счётчик исходящих попыток = 2, `estimatedUSD` содержит обе; повторная POST с тем же ключом не создаёт второй job.
- `GET /api/jobs/by-key` возвращает исходный ID; после `ack` директории для job, audio, segments очищены.
- Негативный тест: `Content-Length` выше предела → HTTP 413.
- Имитация прерванного процесса с сохранённым cached segment: после запуска worker берёт кеш, `attempts` остаётся равен 1; новый HTTP-запрос к провайдеру не требуется.

## Проверка 3 — Chromium UI + UX/adversarial + self-critic

Из-за ограничения браузерной среды `Page.goto(localhost)` возвращает `ERR_BLOCKED_BY_ADMINISTRATOR`.
Для визуальной проверки `index.html + styles.css + app.js` загружены через `page.set_content` с тестовым in-memory адаптером БД вместо реальной IndexedDB.
То есть **реальный Chromium render, но не браузер↔Node E2E**, и не тест Service Worker на настоящем origin.

Проверено на экранах 1440px / 390px:
- Dashboard и библиотека (2 тестовые записи);
- Editor с 138 тестовыми сегментами, 65 сегментов на страницу, изменение текста, переход на следующую и предыдущую страницы;
- экспорт TXT через событие скачивания браузера;
- тёмная/светлая тема; модальное окно; отсутствие кнопок Pause/Stop до начала записи;
- горизонтальное переполнение mobile: `scrollWidth=390` при `innerWidth=390`;
- `pageerror` Chromium: 0 в пройденных сценариях.

Скриншоты в `previews/`, остальные сценарии **НЕ ПРОВЕРЕНО**.

## Quantitative model

Для 4 часов: 14 400 s, 60 фрагментов по 240 s, overlap 0,8 s с двух сторон = суммарно **14 494,4 s** отправленного аудио.
При $0,04/h: **$0,16105** без ретраев, вместо $0,16000 без перекрытия. Это приблизительная *нижняя* стоимость успешной первой отправки, не счёт Groq; при HTTP timeout повтор может удвоить сумму по сегменту.
Модель одного Node worker: 60 последовательных сетевых вызовов на 4-часовую запись. Для нескольких одновременных пользователей это узкое место → фоновые очереди/worker concurrency с rate limiting.

## Four-audit gate

- **A Specification:** браузерное SPA/PWA по российскому ТЗ, не десктопный Electron; сохранение оригинала, доступ к промежуточным данным и ручное подтверждение Groq.
- **B Evidence:** 9 автоматических тестов, Chromium UI тесты со stub DB, source review; нет фиктивных live Groq calls.
- **C Adversarial:** отказ сети на границе upload, restart, cancel во время FFmpeg, malformed provider data, местное переполнение диска, повторные платные запросы, публичный неавторизованный API.
- **D SELF-CRITIC:** correctness 7.5, completeness 6.5, reliability/security (локально) 7.5, usability 8, visual polish 8.5, operability 7 → **общая оценка 7.3/10** для инженерного прототипа, НЕ релиза v1 по полному ТЗ.

### Остаточные дефекты/риски, ранжированы

1. **P0 — НЕ ПРОВЕРЕНО:** реальная четырёхчасовая запись на Windows/macOS/mobile, работа MediaRecorder/IndexedDB и восстановление после power loss.
2. **P0 — НЕ ПРОВЕРЕНО:** реальные ответы и billing Groq, русский WER и тесты 224-token prompts.
3. **P1 — НЕ ПРОВЕРЕНО:** browser→Node через настоящий origin, PWA offline install/service worker, управление permissions.
4. **P1:** нет полного durable queue для многопользовательского сервера, auth/TLS; внешняя публикация теперь намеренно запрещена.
5. **P1:** MediaRecorder chunks + Blob могут быть непригодны после нештатного завершения, не гарантируется восстановление несохранённых данных.
6. **P1:** нет гарантии точной склейки текстов на overlap без WER ручного набора; нет диаризации.
7. **P2:** очередь по умолчанию однопоточная; нет автоматизированного quota/load/4h soak теста и robust retention worker для abandoned jobs.

### Migration seam / следующие шаги

- Сохранить локальную библиотеку IndexedDB; вынести capture engine в desktop adapter при необходимости гарантированной фоновой записи.
- Для многопользовательской версии: авторизация, TLS, media storage, job queue (BullMQ), worker pool, per-tenant rate/cost budget и retention.
- Условия следующего перехода: >1 параллельного длительного job, неуспешные browser quota writes, p95 обработки выше бюджета или недопустимые потери recording chunks.
- Провести реальный user-journey на Windows/macOS с микрофоном и capture tracks, 4-часовой soak + crash, а затем ручную оценку WER на русском эталоне.
