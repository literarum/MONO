# MONO Audio Preparation and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** R-027…R-032/R-035…R-036: измеримая обработка и A/B, сохраненная облачная очередь и проверенные portable-пакеты.
**Architecture:** AudioPreparation анализирует неизменный оригинал, создает согласованную производную до сегментации, а GroqAdapter отправляет только явно выбранный вариант. Один player переключает версии на общей шкале; release gate объединяет реальные OS и browser доказательства.
**Tech Stack:** FFmpeg/FFprobe, Node streams/node:test, Python worker, HTML audio/Web Audio, native build tools/PyInstaller.
**Spec:** ../../MONO-0.5-SPEC.md; 2026-10-16-mono-master.md. Requires CORE library; player UI uses UI components; full release requires both native adapters.

## Global Constraints

Наследует master: оригинал неизменен, никаких автоматических облачных отправок, целая дорожка перед cloud chunks, точность времени и A/B, frozen речевой корпус/WER, 4 h native acceptance, отсутствие Mac или ключа не заменяется stub-победой.

## Review Focus

Anti-phase stereo, короткая/нулевая громкость, устаревший preview, удаленная запись в очереди и недоступный vault/диск после перезапуска. Конкретные проверки AUDIO-1…3/RELEASE-1.

### AUDIO-1: анализ, версии pipeline и согласованная производная

**Files:** Create backend/audio/profiles.mjs, backend/audio/analyze.mjs, backend/audio/prepare.mjs, backend/audio/queue.mjs, tests/audio-analysis.test.mjs, tests/audio-prepare.test.mjs, tests/fixtures/audio/manifest.json; Modify server.mjs, launcher/local_core/library.py.
**Interfaces:** `analyzeAudio(input,{signal}):Promise<AudioAnalysis>` (duration/channels/sampleRate/peak/truePeak/LUFS|null/clipping/noiseHeuristic|null); `prepareAudio({recordId,profile:'original'|'gentle'|'level'|'denoise',signal}):Promise<PreparedVersion>`; `preparePreview({recordId,profile,start,duration:20,signal}):Promise<Preview>`; `PreparedVersion={id,sourceHash,pipelineVersion,profile,analysisHash,frames,sampleRate,pathId}`. Fixed executable paths/argument arrays, cache includes all parameters and source hashes. Unknown key never silently selects a different profile.

- [ ] Freeze independent fixture expectations before DSP changes: impulses at known frames, silence, clean/quiet/noisy speech, stereo anti-phase, clipped input, differing rates/codec padding and invalid media. Freeze the speech corpus/reference manifest described in AUDIO-3 before tuning any speech profile; collection and offline hashing do not require cloud transmission. RED asserts no erased pause, no anti-phase cancellation by naive average, no infinite LUFS/NaN, invalid input fails, duration within one output frame and true peak target ≤−2 dBTP for level/denoise.
- [ ] Implement centralized profiles: original conversion only; gentle highpass 70 Hz; level highpass 75 Hz + two-pass loudnorm I=−19/TP=−2/LRA=11 using whole-record analysis; denoise highpass 90 Hz + afftdn nf=−28 + consistent whole-record loudness analysis. These existing numeric presets are starting candidates, not proof of speech improvement; adjust only against frozen corpus and preserve pipeline version. Auto defaults gentle, denoise recommendation stays disabled until WER gate proves benefit. Stereo route preserves source channels/original and explicitly avoids cancellation before transcription mixdown.
- [ ] Preview uses same global loudness/denoise analysis as full version; if filter state cannot be reconstructed locally, render preceding context or serve corresponding full-derived range. Do not claim local-window loudnorm equals whole-record output. Keep progress/cancel bounded to one preparation worker, superseded versions cannot publish into current UI, partial outputs never become ready cache entries.
- [ ] Run `node --test tests/audio-analysis.test.mjs tests/audio-prepare.test.mjs`; real FFmpeg outputs independently decode/probe, compare impulses/frame count and overlap boundaries. Four-hour generated fixture tests memory/time handling only. Checkpoint DSP gate.
